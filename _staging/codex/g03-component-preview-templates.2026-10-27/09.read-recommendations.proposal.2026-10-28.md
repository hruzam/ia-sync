# Reading recommendations for the calling mechanism

2026-10-28 · Cartan(G03) · deploy-inert draft.
Extends [the thin B proposal](08.thin-B.shell-first.proposal.md) with Majkee's suggestion
to recommend ordinary cat/grep/glob-style access to the calling skill or mechanism.

## Where recommendations belong

The calling skill/mechanism owns available-tool preferences and bindings. A component may
supply optional read hints about the useful reveal operation. The five-field B core stays
unchanged. Existing collection definitions also stay unchanged; a view exposing read_hints
would explicitly add that optional field under its own version.

This keeps provider/tool choices in the calling mechanism and file-specific hints near
their source. Reading recommendations are advisory; the actual task, loader and available
tools determine the action.

## Calling skill/mechanism example

These are proposed preference identifiers, not native Claude/Codex/Gemini configuration keys.

```yaml
reading_profile:
  schema: germline-reading-preferences/draft-01
  operations:
    discover:
      prefer: [native_glob, rg_files, shell_glob]
    preview_prefix:
      prefer: [native_read_range, sed, head]
    locate:
      prefer: [native_search, rg_search, grep]
    read_complete:
      prefer: [native_read, cat]
    project_metadata:
      prefer: [validated_projector]
```

Choose the first permitted, available implementation that can satisfy the request.
An unknown or unavailable binding remains explicit; it is not guessed from a command name.
Local aliases can participate when the caller declares their actual operation.

A validated projector is optional. Without one, ordinary discovery, text search, bounded
prefix reads and complete source reads remain usable. A prefix is labelled prefix; it is
not reported as a validated catalog/select/inspect projection.

## Optional component hints

This example can be additional neutral metadata after the five core fields:

```yaml
read_hints:
  first_sip:
    operation: preview_prefix
    lines: 12
  key_locations:
    operation: locate
    fields: [schema, id, kind, name, description]
  selected_contract:
    operation: read_complete
```

The proposed type is an object of named hints. Each hint has an operation string;
lines is an optional positive integer and fields an optional list of field names.
These hints describe a reveal/read preference. They do not automatically select or
invoke a component, and line count is not a token-budget claim.

The caller can later request project_metadata with collection catalog/select/inspect.
Collection chooses fields; operation chooses how to obtain or reveal information.
Dependencies and the selected body follow the governing loader independently.

## Concrete shell bindings

A mechanism can resolve its own binding into an argument vector:

```yaml
bindings:
  cat:
    executable: cat
    argv: ["--", "{path}"]
  sed:
    executable: sed
    argv: ["-n", "1,{lines}p", "{path}"]
  grep:
    executable: grep
    argv: ["-n", "-E", "--", "{pattern}", "{path}"]
```

The caller supplies validated path, line count and search pattern as separate arguments.
It need not evaluate a shell-command string copied from a component. Native tools can
bind the same operations using their own structured arguments.

Search locates candidate text and retains path/line information. It does not parse YAML:
multiline values, nested fields and matching examples in the body still require proper
parsing for a structured projection. B's short, consistently ordered opening helps the
ordinary first read without changing that distinction.

## Scope of this draft

No native skill/config, active G09 file or existing template was changed.
This proposal supplies examples for the design decision; it installs no mechanism.
