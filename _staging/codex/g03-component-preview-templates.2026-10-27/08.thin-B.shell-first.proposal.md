# Thin B, ordinary CLI reads — revised proposal

2026-10-27 · Cartan(G03), after [Oraculum's consultation](07.oraculum-consultation.md).
Draft for Majkee's consideration. The original eight examples remain unchanged.

## Revised lean

Define a small B foundation now. Use C adapters for existing files and native formats.
A remains a valid small input shape. The common reader contract is the stable boundary;
moving a source from A/C to richer B should not require replacing the consumer.

This revises README.md's initial A/C-first lean. It proposes no corpus migration,
production discovery activation, G09 input change, native role edit or canon lock.

Keep four things distinct:

| Layer | Job |
|---|---|
| Source | Human-readable component declaration and full instructions |
| Normalized record | Typed metadata plus observed source and field provenance |
| Native wrapper | Vendor-specific skill/agent packaging and entry mechanics |
| Collections | Independently versioned projections of the normalized record |

## Small source header

For a newly authored neutral component, place these five fields first, in this order:

```yaml
---
schema: germline-component/draft-02
id: example.tunnel-caretaker.reconcile
kind: function
name: reconcile
description: Inspect an uncertain receipt and identify a permitted recovery action.
---
```

Use a short single-line description so the opening is easy to reveal or search.
Use stable namespaced IDs; name is a display label and path is a locator. Keep these
concepts distinct. Native skills/TOML inputs can retain their existing packaging;
adapters report missing or computed fields honestly.

A readable body can use:

```markdown
# Reconcile

## Scope
The assigned task and governing recovery contract define the actual boundary.

## When to use
An assigned operation has an uncertain result.

## Inputs
The exact operation receipt and its named evidence.

## Contract
Inspect the evidence and apply the governing recovery instructions.

## Outputs
Observed state, evidence, blocker and one next action.
```

These body headings assist navigation. They do not introduce hidden execution or
override the actual governing contract.

## Rich metadata can be added without changing the core

Optional fields need stable types before a collection uses them:

| Field | Proposed type / interpretation |
|---|---|
| scope | Object with summary:string and optional writes_summary:string |
| use_when | List of descriptive strings |
| dependencies | List of objects with reference, purpose and optional condition_summary |
| outputs | List of descriptive strings |
| authority_summary | Descriptive string, without a permission grant |
| authority_refs | List of source/section references |
| context_summary | Descriptive context/read policy, without retention proof |
| maturity | Declared source status |
| stamp | Declared revision token under the existing source's stamp rules |

Dependency declaration order is retained as data. The governing loader supplies executable
order and conditions. Defer a condition language or automatic dependency execution.

The original B purpose/writes object can map explicitly to summary/writes_summary.
Houston's current scope string maps to scope.summary. Preserve the original value and the
transformation in provenance. Never pass both shapes through under one supposedly typed field.

## Reader record

```yaml
record_schema: germline-preview/draft-02
component:
  id: example.tunnel-caretaker.reconcile
  kind: function
  name: reconcile
  description: Inspect an uncertain receipt and identify a permitted recovery action.
source:
  root: caller-selected-source-root
  relative_path: functions/reconcile.md
  observed_absolute_path: "<resolved by reader>"
  sha256: "<computed by reader>"
provenance: {}
adapter: {}
diagnostics: []
```

Source roots are supplied for the current request; this does not propose a global registry.
Keep authored schema version, declared stamp, observed hash and adapter version separate.
A computed legacy ID records its origin and never pretends to be an authored ID.
Keep duplicate IDs as separate source observations and report ambiguity.

Each projected value carries status and origin. Distinguish present, missing, explicit null
and invalid. A computed value can be present while its origin remains helper-computed.
An empty list is an actual value, not a stand-in for missing information.

## Cumulative collections

Example field sets over the normalized record:

```text
catalog: component.id, component.kind, component.name, component.description
select:  catalog + component.scope, component.use_when, component.maturity
inspect: select + component.dependencies, component.outputs,
         component.authority_summary, component.authority_refs,
         component.context_summary, component.stamp
```

Every projection retains its source/revision envelope and per-field provenance, even if a
compact presentation abbreviates it. Collection definitions have their own version.

Expand included collections first; preserve declaration/request order and deduplicate
whole field paths. Use one source snapshot. Reject unknown collection names, unknown
requested fields, inclusion cycles and duplicate YAML keys. Keep missing data distinct
from a misspelled selector. Defer wildcards, overlapping subpaths and implicit deep merges.

Collections project one record. A file-list request returns multiple records. Neither
operation merges the authority or meaning of different cards/controllers.

## Ordinary CLI workflow first

The baseline is ordinary file/shell access for Claude, Codex and Gemini CLI use in this
proposal. AGY is excluded. No custom loader, daemon, service or plugin is a prerequisite
for locating, previewing and reading the source text.

This progression uses the existing draft fixtures:

```sh
preview_root='/home/hruzam/ia-sync/_staging/codex/g03-component-preview-templates.2026-10-27'

rg --files "$preview_root" -g '*.template.md'
rg -n --glob '*.template.md' '^description:.*receipt' "$preview_root"
sed -n '1,18p' "$preview_root/03.function.template.md"
rg -n '^## ' "$preview_root/03.function.template.md"
cat -- "$preview_root/03.function.template.md"
```

These steps locate files, find candidates, reveal a bounded opening, locate body sections,
and read the complete selected source. Equivalent native read/glob tools can serve the
same purpose where exposed. This is not a claim that all three vendors auto-register
our header as a native skill.

The bounded opening is a text prefix; it may truncate metadata. Grep/rg are locators,
not YAML parsers: nested fields, quoting, multiline values and examples in the body make
regex-only extraction insufficient for a validated projection. Retain paths and line numbers.

A future optional projector should take explicit files/file lists and emit ordinary text
or JSON. It can parse a full header locally and return only a collection to the model.
Full cat returns the full text; context saving requires selective delivery and measurement.

## Witness distinction

A preview can expose stamp and hash. Echoing either then identifies a known revision;
it cannot establish that the full contract body was consumed. Record preview delivery and
complete-body delivery as separate observations, with selected source/hash and truncation.
Neither delivery receipt proves understanding or retained context.
