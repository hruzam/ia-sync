# First ideas, before further reading

Recorded 2026-10-27 14:25:53 UTC in this Cartan(G03) turn, before reading local sources or
vendor documentation for this task. This preserves the initial sketch; later findings
and the resulting candidates are in README.md. These are proposals, not adopted doctrine.

1. **A — minimal inline header.** A cheap catalog/selection preview: kind, name,
   description, scope and stamp; full instructions stay in Markdown.
2. **B — richer header with named views.** One file exposes catalog, selection,
   load/dependency and review metadata. Views select fields; they grant no capability
   and prove no instruction consumption.
3. **C — preview adapter for existing files.** Retain existing cards/controllers/functions,
   map their explicit fields into a common record, and keep missing values visible.

Initial cumulative rule: each view includes preceding fields as an ordered, deduplicated
set. Keep source provenance and disagreements visible. More metadata does not confer more
execution authority.

Initial lean: a small shared discovery envelope, optional richer metadata, and reader-owned
view definitions. Use C to bridge existing files.

After reading: candidate A was narrowed to the two familiar skill fields, name and
description. Candidate B now carries the extra germline fields explicitly. This change
preserves the distinction between a familiar vendor shape and our proposed reader format.
