Four distinct decisions should remain separate:

| Layer | Proposed responsibility |
|---|---|
| Source authoring | A small B header for neutral components; existing formats remain valid inputs through adapters. |

| Native wrapper | Runtime-specific packaging, with its own supported syntax and verification. |
| Collections | Reader-owned projections of normalized records; independently versioned. |

This preserves an upgrade path from A/C to richer B without making custom headers a claim about native vendor support.

**Concrete schema correction**

For newly authored B sources, require only:

```yaml
schema: germline-component/draft-02
id: example.tunnel-caretaker.reconcile
kind: function
name: example-reconcile
description: Inspect uncertain operation evidence and identify a bounded recovery action.
```

Define these meanings now:

- `id`: stable, namespaced logical identity. Changing the display name or moving the file does not change it. Multiple sources claiming the same ID remain separate observations until an explicit resolution policy exists.
- `name`: display/discovery label; never the sole lookup key.
- `kind`: component classification, independent of native packaging.
- `description`: short selection guidance, without operational authority.
- `schema`: source-format version, distinct from content revision.

Legacy inputs may lack these declarations. The reader must expose that fact instead of demanding retroactive authoring. A computed identifier stays explicitly computed; it is not promoted into an authored ID.

The normalized record should have separate compartments:

```yaml
record_schema: germline-preview/draft-02
component: {}        # normalized metadata
source: {}           # observed locator and SHA256
provenance: {}       # per-field status, origin and transformation
adapter: {}          # adapter identifier and version, where applicable
diagnostics: []      # ambiguity, unsupported schema or invalid values
```

Use a portable source locator—source root plus relative path—and retain the observed absolute path as reader evidence. Do not author machine-specific paths into component identity.

Keep `scope`, `use_when`, outputs, authority references, dependency descriptions and context guidance optional. Declare their types before admitting them to collections. For example, normalize `scope` to `{summary, writes_summary?}`: Houston’s existing scalar maps explicitly to `scope.summary`; B’s purpose maps there through a documented transformation. Preserve the exact source value through provenance.

Separate authority summaries from resolvable authority references. Existing prose can remain `authority_summary`; a reference should identify its source and section. Neither grants authority. Avoid maintaining a second complete permission contract in frontmatter.

Keep source-declared `stamp` distinct from reader-computed SHA256. The stamp’s existing project meaning remains intact; neither field is a schema version. Reader path, hash, extraction range, adapter version, observation errors and delivery evidence belong exclusively to provenance.

**Dependencies and context need less apparent automation**

The current `loads[].when` mixes lifecycle timing with selection conditions. For the initial schema, treat these entries as dependency descriptions: reference, purpose and a clearly labelled condition summary. Preserve declaration order, but explicitly state that it does not establish executable load order.

Actual ordering, prerequisite evaluation and context recovery remain with the governing loader. Do not introduce a condition language until a consumer needs and can validate one. Otherwise the header becomes an incomplete second loader.

Similarly, `once-per-assignment` cannot establish retained context. Context metadata may describe policy; the reader’s record of delivered bytes and the agent’s current context are separate observations.

**Cumulative collections are sound with tighter rules**

The ordered-union design is simple enough. Its cumulative guarantee holds for one normalized record at one revision.

Add these rules:

- Resolve all requested collections against one source snapshot. A changed source requires a new projection or an explicit revision mismatch.
- Distinguish missing, explicit null, invalid and present values. An empty dependency list must not mean “unknown dependencies.”
- Reject unknown requested field paths; otherwise a typo silently resembles missing data.
- Initially select whole declared fields. Defer overlapping paths such as `scope` plus `scope.writes_summary`, wildcard expansion and implicit deep merges.
- Expand included collections first and preserve request order. Request order may change presentation order, but never selected values.
- Keep provenance associated with every projected value. Any truncation must identify omitted content explicitly.

Projection chooses fields from one record. Cross-file aggregation returns several records. Semantic inheritance combines meanings under a precedence policy. Only the first two belong in this proposal.

Move stable identity into `catalog`, where duplicate names already matter. Maintain source revision in the reader envelope for every projection, even if compact presentation hides the full hash.

Costs remain real: adapters require maintenance; summaries can drift; types require validation; richer previews consume context themselves. Universal B authoring can simplify extraction but cannot eliminate semantic ambiguity or prove better decisions.

## Supplemental operator consideration — ordinary CLI reads

ORACULUM RETURN
CYCLE: G03-preview-01 — supplement

INSIGHT: Thin B should be useful as ordinary text before any custom reader exists.

RECOMMENDATION: Keep the thin B foundation, but make **shell-first readability an acceptance criterion**. Ordinary file access is the baseline for Claude, Codex and Gemini CLI consumers in this proposal; AGY is excluded. No loader, plugin or service should be required to discover a candidate or read its contract.

Place the compact core immediately after the opening frontmatter delimiter, in consistent order:

```yaml
schema: germline-component/draft-02
id: example.reconcile
kind: function
name: reconcile
description: Inspect an uncertain receipt and identify a permitted recovery action.
```

Require a short, single-line description. Optional metadata follows. Use predictable body headings such as `Scope`, `When to use`, `Inputs`, `Contract` and `Outputs`. These improve manual navigation without turning headings into a second schema.

A natural shell-first progression is:

```sh
rg --files components/
rg -n --glob '*.md' '^description:.*receipt' components/
sed -n '1,24p' components/reconcile.md
cat components/reconcile.md
```

These steps respectively locate files, find candidates, show a bounded opening window, and consume the complete selected file. The opening window may truncate metadata or reach the body; it is not a validated header projection. Filename/glob conventions provide useful discovery even where descriptions are missing.

**Grep is a locator, not a YAML parser.** Multiline descriptions defeat line matching; nested fields complicate extraction; matching keys may occur in body examples; quoting and comments change interpretation. Search results should retain paths and line numbers. Semantic field extraction belongs to a proper parser.

A future optional projector can add validated field types, cumulative collections, provenance and explicit missing values. It should accept explicit files or file lists and produce ordinary text/JSON. Authors should not need it to understand their files. The same normalized contract can support that later tool without rewriting source bodies.

The recommendation therefore changes in emphasis: stabilize a small human-readable B header now; avoid requiring elaborate nested metadata merely to prepare for a projector. A/C remain compatible inputs.

Context savings require selective output. A local parser may read every byte while returning only a few fields to the model. Conversely, `cat` of the full file consumes the full returned text; calling it “preview” creates no saving.
