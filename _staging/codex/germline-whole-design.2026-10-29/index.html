01

The philosophy I see

P1 · ONE HOME FOR MEANING

Share the contract

Identity, method and project facts have declared owners. Bindings explain how a particular runtime enters and uses them. Portability preserves meaning without requiring identical vendor packaging. [1]

P2 · AGENTS ARE THE READERS

Make orientation cheap

A small opening helps an agent locate the relevant material. A selected contract supplies the actual obligations. Metadata is a door into the source, not a substitute for it. [2] [4]

P3 · BEHAVIOR NEEDS EVIDENCE

Keep the uncertainty visible

Readable instructions are interpreted by a changing model. File equality, delivery and successful behavior answer different questions. Trials and counterexamples tell us whether the design works. [2]

Accepted foundation recovered from G06: shared agent definitions and a shared program layer must coexist (D1); runtime loading is the working design, with compaction behavior unverified (D2); a project may explicitly attach its local layer, and current packaging is not permanent architecture (D4). Draft 01 understated these accepted decisions. Specific grammar, discovery and cache designs remain to be tested. [10]

Majkee's A1: a deliberately staged combination—orientation and recognition that belong with the agent, plus reusable controllers and functions selected for work. My interpretation: keep the recognition cues small and readily available; resolve the relevant procedure when needed. Reliable spontaneous recognition and retention still need behavioral evidence.

An existing native agent interprets the instruction program. The head integrates results and retains the assigned session pen. A reusable function may live elsewhere, but “from anywhere” means a resolved, permitted source with known provenance—not unrestricted traversal. [5] [6]

B4 · A candidate syntax an ordinary reader can follow

Illustrative plain-language contract, not installed syntax or an executable loader. The proposed benefit is legibility across model grades.

Task: inspect selected source material; return evidence.
Inputs: explicit source roots, question, read budget.

Controller
1. Discover candidate components inside the assigned roots.
2. Preview identity, purpose and provenance.
3. If selection is ambiguous, request more metadata or return the ambiguity.
4. Read the selected function's complete contract.
5. Follow its steps within the task grant; return the result and citations.
   If completion is uncertain, inspect existing receipts before considering retry.
6. Preserve unexpected findings in a separate anomaly return.

Function: extract-one-source
Input: resolved source + revision + requested question.
Steps: read → extract explicit claims → distinguish inference → cite.
Output: claims, locations, unknowns, anomalies.
Stop: missing source, conflicting identity, or exceeded source boundary.

Dependency listings can describe relationships. The governing controller/loader must still supply actual order and conditions. A reference is not execution permission. [4]

OPTIONAL / DERIVED

C5 · Physical preview cache

Can retain extracted records or projections keyed by contributing source revisions, parser/adapter/schema versions and output definitions.

It may avoid repeated extraction. It is replaceable; it is neither authored authority nor model memory. Content checks may still read the source. [4]

Baseline remains ordinary CLI access: file listing → text search → bounded prefix → selected complete read. A projector and cache can help, but neither is required to open a component. Text search locates; it does not validate structured metadata.

C7 · The larger intention: shared continuity

Majkee's clarification: the cache idea also comes from C2C and the possibility of shared representations for agents, respawns, session progress and collateral changes. A physical metadata cache is only one small part of that question.

My proposed distinction: a rebuildable projection can be a cache. An original observation or decision that cannot be reconstructed needs durable evidence custody. A shared space may contain both, but they have different maintenance obligations.

Existing work: the living-session brief already explored this need. The successor's accepted design uses authoritative sources, light entry pointers and explicit revisions; a shared-cache build is deferred. That is the baseline to evaluate, not a reason to suppress this research. [12]

C8 · Small research pass: C2C and AKV

The likely C2C reference is Cache-to-Cache: Direct Semantic Communication Between Large Language Models, also cited in the local brief. It uses a learned fuser to project and combine model-internal KV states. Its reference implementation loads the participating models and projectors. This is different from a durable shared session record. [13]

The authors' related AKV: Cache Engineering for Agents exposes cache dropping and repositioning through an SGLang-based inference system. It is a useful research lead on controllable context, not evidence that existing CLI caches are accessible. [14]

These primary sources were read, not installed or tested. This session exposes no raw KV read/write tool. Cross-model performance, a CLI integration, portable session-memory semantics and a hardware fit remain unverified.

05

Crawlers should find the tails, too

Recover the expected structure, challenge an interpretation, and look for what the structure fails to explain.

D1 · STRUCTURED CRAWL

Follow the known question

Extract explicit contracts, references, kinds, ownership and source facts. Return citations, coverage and missing information. A compact schema makes comparisons easier.

D2 · EXPLORATORY CRAWL

Follow surprising evidence

Look for mixed roles, unusual references, stale assumptions, contradictions and useful exceptions. Follow a few unexpected leads within the assigned boundary.

Keep the raw observation and competing interpretations. Do not force every finding into the released pattern or silently “repair” the outlier.

D2b · Hypothesis scout: Astrobley's third useful mode starts from “we think X—what would challenge it?” It searches for counterexamples and competing explanations. Directed mapper, hypothesis scout and frontier explorer can be assignments to ordinary readers; they do not require three permanent personas.

Majkee's steering, incorporated: “chaotic tails” belong in the research method. Give exploration a source boundary and stopping budget, but leave room for findings that change the model itself.

D3 · What a useful anomaly return contains
Observed: the exact mismatch, exception or unexpected relationship.
Evidence: source path / section / revision; actual words or behavior.
Why surprising: which working assumption it challenges.
Alternatives: at least two plausible readings when unresolved.
Next discriminator: the smallest useful follow-up read or test.
Coverage: what was inspected, skipped and left unknown.

Luna / Terra use: yes, as bounded research readers. The A2 record reports requested Luna/Terra crawlers and head-side corrections; it does not prove arbitrary-model reliability. This synthesis used one newly requested Terra reader plus Houston's consult. Actual backend model identity was not independently witnessed. [8]

D6 · Four additional tails from the exploratory pass
  • Names can hide distinct sources. G09's terminal labels hid different symlink targets while selected bytes remained correct. A neat class map must preserve source identity through its presentation. Next: inspect the bounded label regression. [6]
  • A useful product does not establish the value of its architecture. G09's functional passes coexist with indeterminate germline contribution. Next: check whether the comparison design isolates that contribution. [6]
  • A returned message can disagree with completed work. G07's caretaker reported missing results that durable receipts later showed complete. Next: compare the cited report and receipt summaries; do not resend the task to resolve uncertainty. [5]
  • A shared name need not identify the same project. A2 found a project-read pointer to a mail-stub directory rather than the operator's actual project root. Next: check the locator's declared purpose before classifying it as a broken link. [8]

These are cited research leads. The suggested discriminating reads were not performed; each may change our interpretation.

The head checks load-bearing claims and integrates findings. Houston judges architectural fit. Neither replaces a behavioral trial of the eventual reading/program contract.

D7 · What Zenith and Eagle contribute

Zenith supplies targeted extraction, grep-first reading and unsolicited, cited drift notes. Eagle supplies project orientation, source routing, structure mapping and separate cross-project returns.

These are design precedents, not copy templates. Eagle's fixed paths and newest-first pulse assumptions conflict with the current router/STATUS separation; its nabla-lab shortcut also needs reconciliation with the explicit-root evidence. Borrow the useful jobs and return discipline, then bind them to the actual project's declared sources.
