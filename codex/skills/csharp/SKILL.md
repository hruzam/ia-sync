# cSharp — keep the main pen

cSharp is a posture of Cartan's main thread, not another identity, model setting, daemon, or
child role. The sitting Cartan authors or inherits the RUNBOOK, remains its navigator and sole
`status_owner`, delegates bodies whole, receives navigation and test evidence, and closes the arc
if it can.

This skill is explicit-only. Do not activate it unless @majkee invokes `$csharp` or explicitly
names the cSharp posture for the current RUNBOOK.

## Mount the arc

Resolve the repository instructions, host, worktree, and declared project continuity. Read:

1. the exact `RUNBOOK.md` named by the operator or project router;
2. its current `STATUS.md`;
3. `~/reposoma/raw.guides/runbook/res/csharp-head-protocol.md` completely;
4. `~/reposoma/raw.guides/status/GUIDE.md` before the first STATUS update.

Confirm that the RUNBOOK names Cartan as `status_owner` and carries the cSharp `head_note:`. A
missing RUNBOOK, conflicting gate, different status owner, or unsafe next action returns to
Octopus or @majkee; do not manufacture the arc.

## Hold the navigation edge

Cartan keeps the main pen throughout the arc. For every delegated cycle:

1. Name the cycle, question, allowed evidence, authority boundary, expected return, and recovery
   probe in the existing STATUS. Use only its established fields; do not create another pulse or
   vendor-specific state surface.
2. Delegate the complete body. Cartan may inspect and integrate the return, but it does not reach
   into an artifact whose authorship was delegated.
3. Check the cited artifact or observed output before advancing STATUS. A chat-only return does
   not close a gate.
4. Publish one verified checkpoint and exactly one next action. Architectural, ownership,
   dependency, destructive-scope, or gate curvature returns to @majkee or Octopus.

When execution is required, route it through the RUNBOOK's named working seat. cSharp does not
silently switch itself to Medusa, and a consultant or child cannot trigger that transition.

## Prevailing Oraculum cooperation

Use Oraculum only for an explicitly authorized strategic cycle inside the fixed gate. Cartan
opens the child with the cycle identifier, absolute RUNBOOK and STATUS paths, exact question,
evidence boundary, and analysis-only return contract.

- Retain the returned Oraculum target while the current runtime still exposes it. A completed or
  idle child may remain the prevailing adviser without occupying a running turn.
- Send steering to an active target. Start a follow-up or resume action against the same target
  only when the runtime reports that target as available and the cycle is authorized.
- Never message a guessed identifier, equate the role name with the prior child, or claim that a
  TOML file, tmux pane, parent transcript, or session resume preserved the child.
- Never auto-spawn or auto-recreate Oraculum. If no matching target is available, record the loss
  and recovery edge in STATUS. Create a new child only at an explicit authorized edge, and label
  it as a new child supplied with a bounded recovery capsule.
- The recovery capsule points to RUNBOOK, STATUS, durable returns, and current evidence. It does
  not copy a transcript or represent reconstructed context as restored memory.

Oraculum returns analysis to Cartan. It never owns STATUS or canon, implements, delegates,
addresses @majkee directly as a session head, or wakes Medusa. Cartan verifies the return and
chooses the next cycle, gavel, working seat, or close action.

## Persistence and recovery truth

Record the observed target identifier, cycle, last verified return, and a read-only recovery
probe in the project-approved session surface. Runtime handles and transcripts remain host-local;
portable source contains no session database, message dump, retention promise, or hidden caller.

Parent-session resume, descendant visibility, stable child re-addressing, and saved-turn
retrieval are separate capabilities. Test each after deployment from a fresh session before
calling it live. If any capability is absent, say so and use a new explicitly authorized child
with the durable recovery capsule.

At gate close, perform the cSharp guide's crossed-witness and experience-transfer ritual. Do not
close merely because the last delegated body returned.
