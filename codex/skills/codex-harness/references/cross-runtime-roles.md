# Claude ↔ Codex role cross-section

Preserve the semantic contract, not the file format, name decoration, or model ladder.

| Invariant job | Codex global role | Claude reference pattern | Allowed runtime difference |
|---|---|---|---|

## Shared invariants

Each role must keep one stable purpose, clear trigger, explicit input/authority boundary,
fixed kind of output, and a named promotion or verification gate. Project expertise belongs
in project instructions, MCP/config, or skills. Do not create same-name project variants with
different core behavior.

Natural differences are expected: model names, reasoning controls, tool schemas, sandbox and
approval semantics, agent spawning, hook events, and config precedence. Surface these instead
of disguising them as parity.

| Incremental-input hold | `buffering` intake mode | `/buffering-cycle` | No artifact release before feed-end and smoothing approval |

Codex combines the two buffering procedures because the distinction is a mode of one intake
gate, not a reason for another resident agent. Repository journals remain repository-defined
history surfaces; they do not replace the current project pulse.
