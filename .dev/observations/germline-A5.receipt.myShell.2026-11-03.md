## Harness and protocol qualifications

The four separate native default-role contexts requested fork_turns none and explicit models/low effort. No custom Oraculum route was selected, and no Oraculum canary was returned. Every subject reported no outside reads/tools. Complete independent tool traces, internal reads and effective backend settings were not exposed; neutrality is therefore qualified, not proven. Runtime configuration and the visible Cartan instructions differ from A4's observed Oraculum loader, but absence of its canary does not prove absence of all inherited instructions.

Retrieval was controlled through head messages by instruction. Subjects retained tool capability: this was not a technical filesystem isolation experiment. It tested selection and application from an explicit seven-route entrance, not autonomous filesystem search or training-data familiarity.

Native subjects used different message lifecycles. Readers 01/02 returned intermediate READ messages while running; reader 03 completed native turns with READ requests and resumed the same handle. Reader 04 mixed both. Exact request content, not the native FINAL_ANSWER channel label, determined whether the reader requested a document or submitted its scenario answer. No substitute was spawned, and no feedback, crossover or extra document was sent.

Reader 04 emitted a separate disclosure and repeated its second request in a native final message while the head was admitting that request. Both supplemental messages are retained verbatim in its transcript (158 bytes). They did not cause a second delivery. There are four paired task response exchanges for each reader; reader 04 has six emitted messages if every supplemental message is counted separately. Thus a strict five-message reading of the response-turn cap is not an unqualified PASS. Its bus verdict is REVISE for study-condition qualification, while retaining 12/12 semantic scoring. No corrective turn or rerun is authorized. Native task turns and logical document rounds are not interchangeable cost measures.

One local bookkeeping bug occurred before the first model call: admission persisted, then logging failed on a duplicate timestamp key.
