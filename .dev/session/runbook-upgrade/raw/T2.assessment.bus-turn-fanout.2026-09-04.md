# ASSESSMENT — BUS · TURN · fan-out under a cSharp head

## Assumptions to strike before reading (cheap misread check)

1. The workers are *sessions* (own CLI window, own context), not subagents inside cSharp's
   window. If they are subagents, most of this is void — token-economy.md already covers them.
2. cSharp is the only seat that writes POINTs in this arc. Nobody else dispatches.
3. Only `status_owner` (cSharp) ever rewrites STATUS. Workers and witnesses never do.
4. The human relay is a *carrier*, not a seat — no judgement, verbatim paste.
5. "Concurrent" means two RETURNs may land in either order, not that two seats write one file.
6. The existing `_bus` grammar is worth preserving unless it *cannot* express the case.

If 3 is false, stop — that is a bigger break than anything below.

---

## Verdict

**ACCEPT-WITH-AMENDMENTS.** The amendment lands in **STATUS**, not BUS.

- `turn:` as a grouping coordinate on POINT and VERDICT — **accept** (option A, as written).
- TURN as a fourth BUS kind (option B) — **reject**.
- JOIN as a "specialized VERDICT" — **reject**; the JOIN is the head's STATUS rewrite, which
  canon already names as what closes a cycle.
- The real gap is that **STATUS cannot hold a fan-out** — fix that, and the rest is labels.

## What is actually missing from current BUS

Almost nothing from BUS. Two concurrent cycles 07 and 08 are already legal: separate files,
separate writers, independent VERDICTs. The brief's diagnosis ("which exchanges belong to the
same coordination turn") is a *past-tense* question, and a past-tense label (`turn:`) answers it.

What is missing is **present-tense**:

- `STATUS.in_flight:` is singular; `STATUS.next:` is singular. A head with two delegated cycles
  outstanding has *two* things partially running and nowhere legal to say so. Today it either
  lies (`in_flight: none`) or violates the field.
- `VERDICT.status_rewritten: yes|no` is mandatory per cycle. Under fan-out, VERDICT 07 may land
  while 08 is still open; rewriting STATUS at 07 either advances the position on half a turn or
  writes `no` with a reason the field was not designed for. The closing rule silently
  serializes what the head has deliberately parallelized.
- The seam: only `status_owner` writes STATUS, yet `status_rewritten:` is attested by the
  *verifier*. With crossed witnesses (csharp-head.md), the verifier is often not the owner. Canon
  never says who rewrites in that case. Fan-out makes this seam load-bearing.

Brief §8 stated the tell: "TURN must not create another doing-state." But the open turn *is* a
doing-state — two delegations outstanding, join pending. The honest move is not to deny it but to
put it where doing-state lives, under the replacement law, so it dies at the join.

## Is TURN a real primitive?

**Half.**

- As a *past* object (a receipt): **no**. The receipt of a join already exists — the commit that
  lands the head's STATUS rewrite together with the turn's VERDICTs. A TURN file would be a
  second distilled home for the same facts (PAD GUIDE: *at most one distilled log*), and it would
  carry "the decision that generates the next turn," which the BUS GUIDE forbids verbatim
  (*a VERDICT must not grow a second next-action list*). A file whose content is "these cycles
  belonged together" is a label, and labels go in fields, not files.
- As a *present* object (an outstanding fan-out): **yes** — but its name is not TURN, it is
  `delegated:`, and its home is STATUS. It is the same shape as `holds:`: a line retyped while
  true, gone when its condition passes.

Arity, for the record: a VERDICT judges one RETURN. A JOIN judges a set of VERDICTs and decides
the next position. Different arity, different owner. Calling JOIN a VERDICT keeps the noun list
short and the semantics dishonest. Calling it what it is — the STATUS rewrite — needs no noun.

`turn:` number vs `NN` cycle number: two sequences in one folder is a smell, but a small one, and
`turn:` never appears in a filename. It is the head's dispatch counter, incremented at each
STATUS rewrite that dispatches. Cheap, past-tense, greppable.

## Recommended disk shape

Nothing new on disk. Two fields grow.

```text
<program>-<NN>-<phase>/
    RUNBOOK.md                 participant_2: [coder-a, {claude, sonnet, high}, home]   # agent: Atlas
                               participant_3: [coder-b, {claude, sonnet, high}, office] # agent: Atlas
                               participant_4: [assay,   {codex, gpt, medium}, office, resident] # agent: Cartan
    STATUS.md                  + delegated: · + join_when:   (born on first fan-out, die at join)
    _bus/
        07.csharp.point.md     turn: 03 · to: coder-a
        08.csharp.point.md     turn: 03 · to: coder-b
        07.coder-a.return.md
        08.coder-b.return.md
        07.assay.verdict.md    turn: 03 · status_rewritten: deferred → turn 03 join
        08.assay.verdict.md    turn: 03 · status_rewritten: deferred → turn 03 join
```

**STATUS — two optional fields**, present only while ≥1 delegation is outstanding, obeying the
replacement law exactly like `holds:`:

```yaml
in_flight:   <the HEAD's own partial action, or none — unchanged>
delegated:   # none | one line per outstanding cycle; retype while true, drop at join
  - cycle: 07 · to: coder-a · turn: 03 · awaiting: return | verdict · carrier: @majkee
  - cycle: 08 · to: coder-b · turn: 03 · awaiting: verdict
join_when:   <observable: e.g. 07.assay.verdict.md and 08.assay.verdict.md on disk, both ACCEPT>
next:        <still exactly one — during a fan-out it is "verify the next RETURN on disk;
              join when join_when holds">
```

`carrier:` names the human relay plainly (STATUS style law: *name human ownership plainly*).

**POINT — one optional field:** `turn: <NN>`.

**VERDICT — one field grows:** `status_rewritten: <yes | no + reason | deferred: turn NN>`.
A `deferred` cycle closes when the head's STATUS rewrite for that turn lands; the commit is
the receipt.

## Callsign / roster recommendation

The participant tuple *is* the roster and the seat name *is* the callsign. Do not invent
`Atlas[coder-A]` bracket syntax — the tuple already separates seat from agent. Add one law to
runbook/GUIDE.md:

> **Seat names are unique within a RUNBOOK and fixed at authoring. Two incarnations of one
> agent are two seats.** The agent identity travels as a trailing note on the participant line,
> never in the seat name. `_bus/` filenames use the seat, nothing else.

`csharp` as a seat name is fine; `coder-a` / `coder-b` are fine. The 2026-09-02 audit's
open item — two Atlas incarnations becoming ambiguous — closes with that one sentence.

## cSharp operating loop

1. Rewrite STATUS: `delegated:` lines for each cycle about to dispatch, `join_when:`, `turn: N`.
2. Write POINTs (`turn: N`). Commit STATUS + POINTs together.
3. Yield. (Human relays, or dispatch does.) Nothing on the bus moves without a file.
4. Per RETURN on disk: verify, or route to the named witness. VERDICT lands with
   `status_rewritten: deferred: turn N`. Retype `delegated:` line (`awaiting: verdict` → gone
   when its VERDICT exists).
5. When `join_when` holds: rewrite STATUS — `delegated: none`, `checkpoint:` advanced with
   evidence pointers, one new `next:`/`expected:`, and `turn: N+1` if dispatching again.
   Commit STATUS with the turn's VERDICTs. **That commit is the JOIN.**
6. At gate close, csharp-head.md's ritual unchanged: promotion manifest, transfer, prune.

## Failure modes

- **Parallel returns.** Non-issue. Separate files, separate writers. Order of arrival is
  visible in git, not in filenames, which is correct.
- **Late return after join.** Head joined turn 03 on 07 alone (STOP or BLOCKED on 08), moved to
  turn 04; then 08's RETURN lands. It is still cycle 08, still valid, still gets a VERDICT with
  `turn: 03`. Its finding enters the *current* STATUS as curvature or a `holds:` line. No
  renumbering; history stays true; the VERDICT's `turn: 03` says exactly what happened.
- **Stale turn.** Worker holds POINT 07 (`turn: 03`); head is at turn 05 when the RETURN arrives.
  Same as above — the verifier judges relevance in VERDICT `## Curvature`. `turn:` is what makes
  staleness *legible* instead of silent.
- **Worker disappears.** The `delegated:` line survives only if retyped as still true. Every
  STATUS rewrite forces the head to look at it. A vanished worker is closed by the head writing
  VERDICT 08 with `disposition: BLOCKED` (RETURN absent, cited as such) and, if needed, a new
  cycle to a replacement seat. Nothing hangs invisibly — that is the replacement law doing its job.
- **Correction / reopen.** New numbered cycle. Same `turn:` if it is still the same coordination
  decision, new `turn:` if the head re-dispatched. No new mechanism.
- **Human relay error** (POINT 07 pasted into coder-b). Mechanically detectable: the RETURN's
  filename seat (`07.coder-b.return.md`) mismatches POINT 07's `to: coder-a`. Verifier records
  it as curvature; head decides whether the work is usable. Recommend the POINT's `to:` be the
  first line the worker echoes back in RETURN field 2 — a one-line self-check the carrier cannot
  fake. Do **not** build a PAD for the relay unless relay steps genuinely branch; `carrier:` in
  `delegated:` is enough for a straight paste.
- **Verifier ≠ status_owner.** The witness writes `status_rewritten: deferred`; only the head
  rewrites. This resolves the seam for the fan-out case and, as a side effect, for the ordinary
  case too — worth stating as law regardless of this proposal.
- **Two dispatchers.** If any seat other than the head writes a POINT, `NN` sequence ownership
  breaks. Under cSharp this is excluded by csharp-head.md ("delegates every body of work");
  state it as a hold in the RUNBOOK's known constraints, not as BUS law.
- **Worker spawns its own executors.** Inside its window (token-economy.md). Never on this bus.
  Its RETURN carries the summary.

## Push-back

**On reinventing the harness.** Claude Code and Codex both ship subagent fan-out and a
background/Agent-View dispatch. If the workers are subagents in cSharp's window, none of this
is needed — the harness already joins, and token-economy.md already prices it. The proposal is
justified *only* because the workers are full sessions, across hosts and possibly vendors,
and the file plane is the sovereign record. Write that justification into the RUNBOOK that
first uses it, per the golden rule: name the native change that would retire it (a cross-host,
cross-vendor subagent join with a durable receipt — not shipped by either vendor as of today).

**On making BUS intelligent.** Asymmetry's worry was right and this assessment honours it by
leaving BUS dumb: a label on existing files, nothing else. All coordination intelligence stays
in the head and its STATUS. If a future revision finds `turn:` insufficient, the answer is still
not a BUS kind; it is a richer `delegated:` block.

**On the brief itself.** Its cleanest contribution is §8, and §8 is where it misread its own
canon: it tried to make the fan-out *not* a doing-state because STATUS is the only doing-state.
The right inference runs the other way — if STATUS is the only doing-state, the fan-out goes
into STATUS. Once that flips, options A and B both dissolve.

**On the semi-generated BUS.** majkee's note that BUS was semi-automatically generated and may
be reshaped is orthogonal to this amendment and should stay so. The six-field RETURN and the
verification table are heavy for surgical-grade executors; that is a *grade-per-schema* question
for the next reshaping, not a fan-out question. Park it as its own brief. One mountain.

**On timing.** This should not be gaveled from assessment alone. One live fan-out run — two
worker sessions, one human carrier, one witness — with the `delegated:` block written by hand
before any guide text changes. If the block is never retyped stale, and the `deferred` VERDICT
never confuses a cold-resuming agent under the 03:00 standard, then amend. The brakes on the
RUNBOOK arc already say measure before amend; this is the same law.
