# RAW — how the field runs sessions, and what that says about this bed

## AXIOMS  (strike cheaply before reading on)

1. The community's convergence on markdown-as-substrate was reached from pragmatism,
   not sovereignty. Same destination, opposite direction. → #convergent-substrate
2. Surface choice (CLI vs desktop vs cloud) is ergonomics, not work-shape.
3. The split-and-handoff vs stay-and-compact doctrines are cultural, not mechanical.
   No survey exists; prevalence is unclaimable in either direction.
4. Autonomy scales with **scoreability**, not with model quality.
5. A durable file that has drifted from reality is worse than no file.
6. Prose is not enforcement. A law with no breach signal is discipline, not contract.
7. The bed's real bound is structural (fields, gates, one decision surface), not lines.
8. Every mechanism here produces order. None of them senses whether it earns its cost.
9. Prior art now exists for two components previously believed novel.
10. Twelve anchored remedies are still twelve. Volume is its own failure mode.

## PART 1 — THE FIELD RECORD  (dated 2026-09-02/03, treat as weather)

### #surface-is-not-shape
Both vendors ship several surfaces over one engine. Codex persists sessions to disk and
resumes across CLI / IDE / desktop / cloud — one account, one allowance, so the choice is
low-stakes. Claude Code splits by job: CLI when the work is scriptable and git-native,
desktop when supervising. Nobody reports the surface changing what the work *is*.

### #two-doctrines
- **(a) split** — reset often into fresh sessions, carry a written handoff. Buys clean
  attention, costs rationale.
- **(b) hold** — stay in one thread, compress in place when it dilutes. Buys the reasoning
  trail, costs attention hygiene.

Same operation (lossy curated compression), different **location**: across a boundary vs
inside the session. The doctrines track each community's tooling investment, not a
capability difference. #culture-not-capability

### #tier-routine
Strong model plans, cheap model executes, strong model reviews. Shipped as an automatic
handoff in at least one harness. A stricter variant has the strong model never execute at
all. The sharper framing is routing by **uncertainty**, not by cost: cheap when the path is
clear, strong when ambiguity or architecture risk rises.

### #unattended-is-a-loop-not-a-session
Overnight runs are usually **many short runs**, not one long one. The mechanism:
non-interactive mode with permissions pre-granted, a task file, a fresh process per
iteration, and **git history as the memory between runs**. What accumulates is commits, not
context. The verification chain (run agent → run tests → branch sits for the human) is what
makes it safe to leave.

**The loop script, sourced.** Original form (Huntley, 2025-07-14) is a bare infinite loop —
prompt file piped to the agent, repeat, **no completion sentinel**. The disciplined variant
I had described from memory (PRD + progress file + iteration bound + COMPLETE marker) is
Pocock's `afk-ralph.sh`, a later descendant. → #ralph
The stop condition is the whole design. Without one it runs until killed or the budget dies.

**Worktrees.** One repo, several checkouts, separate branches — isolation on disk instead of
in context. Reported ceiling ~3–5 concurrent; one team's 20 agents degraded to an effective
2–3. **The reviewer is the binding constraint, not the harness.** Without a clear scope per
session, parallel agents produce competing rather than complementary changes.

### #over-preparation-threshold
The one crisp rule the field offers: **if you could describe the diff in one sentence, skip
the plan.** Backlash against heavyweight spec tooling is documented. Answers the
hour-vs-seconds problem: small work never enters the enclosure.

### #retirement-rule (Ronacher)
If you automated it and then stopped using it, it failed — delete it.
Three repetitions before automating; a manual acceptance check first.
There is **no established cross-vendor process-retirement lifecycle**. Process accumulates
by default. This is the sensor the bed lacks. → #missing-sensor

### #length-evidence (corrected — read this before quoting a number)
Two studies conflated in my first reading:
- 438-task evaluation: **no significant general success gain** from a context file at all;
  ~20–23% higher inference cost for **generated** files; binned analysis found **no clear
  relation** between word count and success or cost. It explicitly did **not** establish an
  optimum.
- 124-PR study: presence associated with lower median runtime and fewer output tokens; did
  not evaluate correctness or length as the causal variable.
- 288-run study over 17 tasks: no measurable correctness effect; evidence called contradictory.

Anthropic's ~200-line target and Codex's 32 KiB accumulation cap are **loader budgets**, not
demonstrated quality thresholds. Any "past N lines it degrades" claim (including one I made
in this thread) is folklore until sourced.

### #context-rot
Stale code-element references found in **23.0% of 356 repositories**. Persistent context is
not automatically fresher than a transcript. The unresolved tension is not memory-vs-no-memory
but **continuity vs current evidence**.

## PART 2 — THE OPERATOR'S SHAPE  (@majkee, this thread, in his own frame)

### #the-c-shape
Not a line, not a loop — an arc leaving the primary and returning to it.

1. **intention** — thin seed, author-signed. *Greet this, this is what I'm after.*
2. **substrate → runbook** — built up by the writing assistant. Cheap hands on drafting.
3. **big player returns** — maintains, tightens. Authorship already spent, so its job is
   correction, not creation.
4. **specialist caller** — spawned or given its own session, only when genuinely needed.
   → still open: spawn-vs-session is an isolation call or a cost call. #open-leg-four

**The non-obvious move:** everyone else starts at *planning*. This starts at *intention* and
lets the substrate be built, which is why the strong model's role becomes maintenance.
The field record has no equivalent of the seed-precedes-plan leg.

### #runbook-is-the-enclosure
Not one file among four — the frame the work happens inside. Consequences:
- Small work ("change something on this blade") never **enters** the enclosure. It's weather.
  It doesn't earn walls. This is the hour-vs-seconds answer, and it matches the field's
  one-sentence-diff threshold arrived at independently.
- Discovered tasks are **born inside** the enclosure. They need no new leg — they land in
  the volatile file, and graduate to the human queue if they turn out to be human-blocked.
  The enclosure doesn't have to have anticipated them. It only has to contain them.

### #chapters-already-exist
The numbered siblings **are** the chapters. `<program>-<NN>-<phase>` = book / order / name.
Chaptering is by **gate count**, never by line count. A long single-gate RUNBOOK is long
because it reproduces what `references:` should point at.
Still homeless: the **program** level above the siblings — ordering rationale, program exit,
the prior-art verdict (which is program-scoped, answered once, not once per sibling).
→ parked pending one closed program's post-mortem. #open-program-level

### #single-author-is-the-freedom-condition
The rule is not "subfolders are free." It is:
> **A surface is free when one seat writes it, and law-bound when two seats do.**

The operator's own learning file is shapeless because it has one author. The cross-seat
exchange is the most tightly specified surface in the bed because shape *is* the protocol
there — it's the only thing making a reply readable by a seat that didn't write it.

### #freeze-the-pointer-not-the-payload
Every previous attempt failed by fixing the payload; the shape got driven into a new form by
the next situation and the bureaucracy followed. What survives is the **reference**: the
agent is told *go look there*, not *a file of this shape must exist*. A folder allowed to be
empty is not a gap. When the learning file is missing, nobody cares — and if it's missing
when it shouldn't be, that itself is the signal.

### #journal-rejected-with-cause
Tried, failed. Operator's stated cause: many voices in one file — a chorus, not a record.
Field's sharper cause: **byte-level atomicity would not solve semantic races.** The working
alternative in both ecosystems is a task store plus per-agent mailboxes — which is what the
bed's single-writer-per-file exchange already is.

### #the-finding-neither-of-us-had
**No physical concurrency model under the single semantic authority.** Two seats read the
state file at revision A, advance different edges, and both write. Every written law is
obeyed; one current truth is lost. No revision field, no compare-and-swap, no atomic rename,
no named owner. Related: cycle-number allocation in the exchange is undefined — two seats can
legitimately pick the same next number.

**Severity is conditional and currently LOW.** The operator serializes: work happens on one
host at a time, with the second host used opportunistically for human sittings. The audit's
own text concedes the laws are adequate for a strictly serialized solo operator.
→ Recorded as a **named latent**, not a build. Trigger: the first time two seats advance the
gate inside the same window, revision-check the state file before anything else.

### #host-provenance-gap  (found here, invisible to the audit)
The state file carries a host field — but it is a **replacement** snapshot, so every rewrite
erases the previous host. It answers *where am I now*, never *where was that done*.
Host provenance cannot live there by construction.
By the bed's own seam test it belongs where things survive the gate: the human-sitting
header (already the raw receipt), the reply's frame block, and the evidence artifact itself.
One line in two guides. Not a mechanism.

### #mirroring-is-an-unstated-law
The bed mandates absolute paths in every prompt. The audit called this host-specific and
doomed, and recommended repo-relative paths. **That objection assumes divergent trees.**
The operator maintains 1:1 folder placement across both machines, which makes the
absolute-path law sound and *copy-pasteable-everywhere* true rather than false convenience.

But the mirroring appears in **none of the four guides**. Every absolute path in every prompt
silently depends on it. → The correction is not to adopt relative paths. It is to **state the
mirroring as law and name its breach signal**: if the trees diverge, the absolute-path rule
fails everywhere at once, quietly.

## PART 4 — PRIOR ART FIRES ON OWN WORK

The epistemic gate (*does this already exist as vendor delivery, before building*) fired
twice on this operator's own components. Both hits are real; both leave a residual.

### #cross-vendor-consultation
**Exists.** An official first-party plugin now provides read-only and adversarial review,
delegated tasks on fresh or resumed threads with model/effort choice and background
execution, job status and stored results, transcript transfer into a persistent thread with
a resume handle, and an optional stop-hook gate. Official import flows carry setup, projects
and recent chats between agents.

**Residual, and it is real:** every delegated reply receiving a distinct verifier's
claim-by-claim disposition; project-owned assignment with scope, forbidden operations and
done-when; evidence digests; git-owned records reviewed with the code; survival past the
vendor's own retention; **cross-machine** work (the plugin uses the same machine's local
install and checkout).

**Verdict: complementary with a shrinking residual.** Vendor plane for transport and job
control. File envelope only when cross-machine, high-risk acceptance, durable provenance, or
legibility after both local threads are gone. For a casual same-machine question the file
form is redundant. Do **not** keep a parallel long-lived relay or duplicate transcript.
Consolation: an existing toolkit retired its subprocess relay while its file/git handoff
conventions survived — the same conclusion this bed reached independently when it excluded
headless single-shot invocation.

### #competence-escalation
**Exists.** A native advisor mechanism now ships for pure decision consultation, at lower
latency and cost than spawning a senior agent.
**Residual:** spawn-a-senior survives only where the senior uses distinct tools, context or
permissions, produces a durable artifact someone actually consumes, or finds defects the
native path misses. Otherwise it is theatre.
**Observable for retirement:** across ~20 escalations, if the senior makes no tool call,
produces no consumed artifact, and changes no decision — delete the pattern.

## PART 5 — WHAT IS AHEAD, AND SHOULD NOT BE TRADED AWAY

Independently ranked ahead of ordinary field practice:

- writing the **in-flight** field *before* a risky action, naming possible side effects
- an **interpreted read-only recovery probe** — testing the mechanism, not the convenient
  residue (a presence check is not a probe: a marker file can exist while the thing is dead)
- exactly **one next action + one expected observation**
- **a reply is a set of claims, never evidence** — including claims from another agent
- **mandatory remaining-uncertainty**; `none` is a value, silence is ambiguity
- **curvature**: when map and artifact disagree, the disagreement *is* the artifact — name
  it, verify both sides, never flatten to the tidier version
- explicit **promotion boundary** before pruning
- optional files **born on need**, never pre-created
- authoring surface separated from live deploy target

The cold-resume standard is an excellent **acceptance criterion**. It has never been measured.
That is the cheapest high-value move available. → #measure-before-amending

## OPEN  (underlined, not resolved)

- **#open-leg-four** — specialist caller: spawn or own session. Isolation or cost.
- **#open-program-level** — what holds ordering rationale, program exit, and the
  program-scoped prior-art verdict above the numbered siblings. Parked pending one closed
  program's post-mortem. Evidence to collect: what was promoted, what got re-derived, and
  whether a prior-art question was answered twice.
- **#open-ledger** — gaveled: it stays. Field evidence supports the failure it addresses
  (wrong frame becoming active, intent disappearing while code survives, rejected approaches
  returning after compaction under a cleaner name, machine-local memory not crossing hosts).
  The maintenance condition is #context-rot: a ledger that rots is worse than none.
- **#missing-sensor** — nothing yet detects that a leg has stopped earning its keep.
  Ronacher's rule is the cheapest instrument; the maintainer's report is where the evidence
  would naturally accumulate at no extra cost.
- **#named-latent-concurrency** — see above. Not a build. A trigger.

## BRAKES HELD

- No installer script until the same runbook shape survives 3–4 runs **without reshaping**.
- No revision/lock tooling until two seats actually collide.
- No adoption of the twelve audited remedies as a set. Volume is the failure mode the
  operator has already hit three times.
- Measure the cold resume **before** amending anything the measurement might redirect.
