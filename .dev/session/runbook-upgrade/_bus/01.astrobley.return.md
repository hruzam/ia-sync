## 4. Mismatches discovered

### BUS-first judgment

The smallest coherent model keeps exactly three BUS kinds. A **cycle** remains one
POINT → RETURN → VERDICT exchange. A **turn** is only the stable coordinate grouping the cycles
opened by one head decision. The open turn is present state and therefore lives in STATUS as
`delegated:` plus one `join_when:`; after closure, `turn:` on POINTs and VERDICTs is the
past-tense grouping receipt. A TURN file or a “join VERDICT” would duplicate STATUS and distort
VERDICT arity.

The shared mechanism belongs in one new RUNBOOK chapter because it crosses RUNBOOK roster and
head authority, STATUS present state, and BUS receipts. RUNBOOK/BUS/STATUS GUIDE bodies should
only label and point to it. This satisfies the guide-writing rule that a chapter is the sip unit
and prevents three subtly different copies of the same coordination law.

### Where the candidate fails under pressure

1. **Late RETURN after a branch was abandoned.** The assessment says the head can write a
   BLOCKED VERDICT while the RETURN is absent. Current BUS law instead says a VERDICT judges one
   RETURN and requires a `return:` path. That is a direct contradiction, not an implementation
   detail. If the fold permits a narrow no-RETURN VERDICT, a later RETURN cannot receive a second
   VERDICT in the same cycle. It must stay historically late and be assessed through a new cycle
   in the currently open/new turn; the original files are never renamed or overwritten.

2. **Late VERDICT and `deferred`.** A newly authored `deferred: turn NN` may name only the turn
   that is open at that moment. A late VERDICT after its original turn joined must say
   `no + reason` and point at the current curvature/hold, or defer to the currently open turn.
   Historical deferred markers do not become invalid merely because their once-open turn later
   joins; the “open” constraint applies at authorship. The countersign does not make this tense
   distinction explicit.

3. **REVISE.** Current BUS law allows a VERDICT disposition of REVISE and says a VERDICT closes
   a cycle. The countersign says “REVISE is not terminal.” Both can be true only with explicit
   level separation: REVISE closes that cycle but does **not** satisfy the turn branch. The head
   opens a new corrective cycle in the same turn, links it to the revising VERDICT in the POINT,
   and replaces `join_when:` with the new observable obligation. Only ACCEPT, STOP, or BLOCKED
   satisfies a branch for joining.

4. **One-open-turn conflict inside the countersign.** Lines 29–33 require one open turn and
   REVISE to remain in it, while lines 94–96 give an example where a corrective cycle in turn 03
   appears after a turn-04 POINT. That example violates its own invariant. What may interleave is
   artifact arrival: a late RETURN/VERDICT from closed turn 03 can arrive after a turn-04 POINT.
   New POINT dispatches for two different open turns may not interleave.

5. **Crossed witness versus STATUS ownership.** The current BUS requires every cycle-closing
   VERDICT to confirm the STATUS rewrite or explain BLOCKED, while cSharp makes the head the
   `status_owner` and requires crossed witnesses. A witness must not rewrite the head's STATUS.
   `status_rewritten: deferred: turn NN` is therefore necessary as a past-tense attestation that
   the open turn's owner-side join is still owed. The head then reads and checks VERDICT contents
   before replacing STATUS. File presence alone never discharges the edge.

6. **Human relay mismatch.** “Paste one absolute POINT path” is sufficient transport only if the
   receiver first checks that POINT `to:` and the seat encoded by `return_to:` both equal its
   fixed RUNBOOK seat. Otherwise a wrong worker can either forge the intended filename or create
   an unexpected filename. The chapter should make mismatch a stop-before-work condition; the
   carrier reports it back through the transport, the outstanding STATUS row remains true, and
   the head decides the next BUS cycle. BUS must not pretend it supplies delivery or read-state.

7. **Interrupted head.** The vulnerable edge is VERDICT-on-disk before STATUS replacement.
   During fan-out, the instance STATUS `recovery_probe:` must reconcile every `delegated:` row
   against the matching POINT, RETURN if any, and VERDICT **contents**: cycle, turn, seats,
   disposition, and `status_rewritten`. Presence-only probing repeats the stale-residue failure
   already rejected by STATUS law. Disk/STATUS mismatch is the partial state, not grounds to edit
   the witness's artifact.

8. **Commit as JOIN is not established law.** The assessment says the commit containing STATUS
   plus VERDICTs is the JOIN. Current guides require history in git but do not require every
   working transition to be an atomic commit, and some seats lack commit authority. The chapter
   should define join as the verified `status_owner` STATUS replacement after `join_when` is met;
   durable commit policy remains repository/operator policy unless the live test proves a
   stronger invariant and the gavel adopts it.

### Proposed `runbook/res/fanout-turns.md` chapter outline

Frontmatter, exactly:

```yaml
---
title: cSharp fan-out turns — full-session coordination without a fourth BUS kind
chapter-of: runbook
---
```

Normative outline:

1. **When to use it** — only when one persistent head coordinates two or more independent full
   CLI sessions whose RETURNs may arrive in either order; native in-window subagents remain under
   token-economy and do not create this file-plane mechanism.
2. **Authority split** — RUNBOOK fixes unique seat names, roster, head and `status_owner`; STATUS
   owns the one open turn; BUS records only POINT/RETURN/VERDICT history. Human relay is transport,
   not a fourth authority.
3. **Coordinates and invariants** — cycle `NN` orders exchanges; `turn: NN` groups one head
   coordination decision; exactly one turn, one `join_when:`, and one `next:` may be open; no TURN
   file and no specialized join VERDICT.
4. **Opening a turn** — the head writes all POINTs and replaces STATUS with bounded
   `delegated:` rows, one observable `join_when:`, a content-checking `recovery_probe:`, and the
   singular `next:`/`expected:` before relay. Each receiver validates `to:` and `return_to:`.
5. **Bounded STATUS vocabulary** — each row has only `cycle · to · turn · awaiting` and optional
   `carrier`; `awaiting` is exactly `return` or `verdict <seat>`. No timestamps, sent/acknowledged,
   progress, or notes. `carrier` exists only when a named human action matters to recovery.
6. **Per-cycle crossed verification** — RETURN stays unchanged; the witness checks the actual
   artifact and writes a VERDICT carrying the POINT's turn. Only `status_owner` replaces STATUS;
   another witness records `status_rewritten: deferred: turn NN` while that turn is open.
7. **REVISE and join** — REVISE closes its cycle but opens a linked corrective cycle in the same
   turn and replaces the branch's `join_when` obligation. ACCEPT, STOP, or BLOCKED is terminal for
   a branch. Join occurs only after every current obligation is checked, then the owner replaces
   STATUS and may open the next turn.
8. **Missing and late artifacts** — define the gaveled choice for an absent RETURN; prohibit
   second files per direction; route late material through a new assessment cycle without
   rewriting history; allow new `deferred` only to the open turn.
9. **03:00 recovery** — compare STATUS rows with POINT/RETURN/VERDICT contents, name every
   mismatch as partial state, preserve holds, and take one safe next action. Include interrupted
   head, stale relay, crossed seat, REVISE, and late-return examples.
10. **Limits and retirement trigger** — no scheduler, inbox, read-state, BUS automation, or
    vendor syntax; retire the file-plane delta if a cross-host/cross-vendor native durable join
    supplies equivalent receipts.
