## Why this session exists

`claude/agents/oraculum.md` is a substantial Claude-side strategist with a direct-entry
topology, vendor tool list, and Bash hook. A mechanical port would duplicate the existing
Cartan controller, bypass the declared protocol skills, and introduce undeclared Codex behavior.
This session establishes the minimal semantic fold before any deployed `codex/` source changes.

## Fixed facts

- Cartan is the Codex controller and integration owner; Octopus, Medusa, and Buffering are
  Cartan postures/procedures, not new resident identities.
- The existing global Codex roles cover architecture, challenge, research, implementation,
  verification, and harness creation, but no role currently carries Oraculum's deep strategic
  planning contract.
- `codex/agents/` is the portable authoring surface and `~/.codex/agents/` is only a deploy
  target. The Codex harness requires a proposal and @majkee confirmation before an agent source
  is written.
- `$octopus` plans and parks; it neither edits a future agent TOML nor spawns its recommended
  executor. `$buffering` supplies the retained substrate → architecture → execution release
  gate.
- The Claude Bash whitelist is a Claude hook with observed inheritance behavior. No Codex hook,
  tool list, model name, or direct-invocation rule is presumed portable.
- A custom-agent TOML declares a role's static configuration; it is not presumed to hold an
  active child process, retain a subagent lifecycle, or store a transcript. The supported
  runtime/session mechanism must be identified and proved separately.
- `DOPLU discipline` has no matching definition in the ia-sync or available shared-guide search;
  it is a named unresolved constraint, not a behavior to infer.
