## Selected A1 shape and deliberate differences

- `germline/agents/oraculum/identity.md` owns the scientific personality, shared
  method, evidence/return contract and the explicit child/direct-planning authority table.
- Two vendor bindings map mechanics. Native envelopes retain model/effort and tools;
  wrappers load identity → binding → optional project addendum, using Houston's current
  runtime-load pattern. No Houston card set is imposed on Oraculum.
- The Codex child keeps its existing caller list, read-only/non-delegating scope and
  exact return fields. A new main profile supplies direct planning entry without
  changing that child's scope. Main planning writes/session ownership require a
  concrete operator assignment; neither route gains canon or implementation authority.
- The former Claude phrase “not spawned by Houston” is replaced by the shared, bounded
  child-consult route, including Houston inside Houston's own authorized scope.
  Direct planning no longer makes executor dispatch an automatic consequence of a plan.
  These are visible authority choices, not a claim of identical runtime capabilities.
- Legacy hardcoded project-plan paths and mandatory startup/reflection questions
  give way to the applicable repository read order and the operator's requested methods.
  Native hook/settings remain in the Claude envelope; no hook is copied into Codex.

This study supplies the process lesson: classify a name's live relationship before
folding it. A transferred pointer (Astrobley) and two active personalities (Oraculum)
require different treatment. A common file count or agent name is not the contract.
