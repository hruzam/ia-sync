This is the external CACHE attached to the A1 continuous agent-build line. Each

## Read and update contract

- Read this thin cache on entry; follow only the sources needed by the current task.
  For each inherited claim answer: what may be inherited, what must be verified,
  and which change would invalidate it. Missing evidence remains unknown.
- One operator-selected build head writes the shared cache at a time. In parallel
  work, each head writes its own raw/CACHE.md or proposed cache delta; merge shared
  notes after reconciliation. No competing STATUS or implicit cross-session pen.
- Each build owns its raw/CACHE.md: volatile hypotheses, source anchors and lessons
  for that stream. Keep it thin, prunable and non-authoritative. An actionable hold
  belongs in STATUS; a claim needed for acceptance needs a durable evidence receipt.
- At closure, propose only checked reusable lessons for this file, with source
  revision, observed/reported/inferred label, scope and verification limit. Retire
  invalidated notes explicitly; preserve provenance before pruning a task bed.
  Promotion into global identity, guide or canon remains a separate reviewed act.

## Generic build loop

1. Resolve actual cwd/host, instructions, ownership, deployed/source state and task.
2. Inventory existing roles, skills, programs, cards, regimes and parked work by
   purpose. Trace original sources before proposing another native role.
3. Extract invariant job/authority/return; allocate runtime mechanics to bindings,
   reusable procedure to skills/programs, distinct operations to earned cards and
   task-specific paths to project layers. Preserve useful native asymmetry.
4. Present one concrete source/entry/activation/verification proposal. Honour an
   already explicit release; do not manufacture repeated permission gates. A new
   meaningful role or authority lock still belongs to Majkee.
5. Author the smallest approved source fold on ia-sync's table. Keep history and
   private/runtime state out of portable source. Deploy only the released slice.
6. Check syntax, pointers and source transitions; then separately witness actual
   loading, main/child scope, outputs and refused operations on released routes.
7. Review independently where required; state pass/partial/deferred with evidence.
   Update the owning STATUS and return a compact lesson/delta for the next build.
