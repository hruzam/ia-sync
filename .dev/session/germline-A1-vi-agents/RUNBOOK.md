## Five-phase production workflow

| Phase | Work and role | Decisive return |
|---|---|---|
| P1 · local harness comparison | Bounded reader/subagent compares actual Claude/Codex sources by purpose, entry, authority, returns and native mechanics. Search existing roles/skills/programs/cards/regimes first. | Reuse/difference map, exact sources/revisions, reading depth and omissions. |
| P2 · vendor harness research | Bounded researchers answer the unresolved capability questions that can affect this build, using current primary sources. | Dated findings, contradictions/access limits and implications; shared vendor receipts may serve later groups. |
| P3 · building strategy | The head integrates; Astrobley supplies the programming/feasibility voice and Houston a bounded consult on actual structural/authority questions. | One concrete source/entry/authority/verification proposal, smallest alternative and decisions still owed. |
| P4 · implementation | Natural Luna for sufficiently mechanical bounded work, Terra for coherent changes needing judgment, through available native routes and disjoint file ownership. | Scoped diff, meaningful checks and explicit deviations; one head integrates. |
| P5 · tests and audit | Independent verification/audit checks the promised contract; the writer does not self-accept its design. | Verdict tied to exact artifact/runtime/host/entry revision and exercised routes, useful-task/boundary evidence and remaining limits. |

Phases do not require five new conversations, unconditional spawns or repeated
approval rituals. Record done/reused/not-needed/deferred with a reason and receipt.
Reuse adequate local/vendor research; refresh consequential volatile claims or
invalidated assumptions. Batch independent reads; sequence decisions/mutations.
Give each consultant a distinct question and only the evidence it needs.

Existing harness_builder/researcher/implementer/Astrobley/verifier contracts are
reuse targets, not names to clone. Respect actual native capabilities and fixed
model/effort pins. Requested/configured settings are separate from observed runtime.
Shared identity owns stable job/authority; bindings own native mechanics; skills and
programs own procedures; earned cards distinguish genuinely different operations.
Project layers supply local paths and constraints. Different tools, hooks, prose or
delegation patterns are compatible with the same useful function.

## Ownership, evidence and sitting handoff

One named head owns STATUS, integration, schedule entries and common CACHE at a
time. A changed head is explicitly handed the same line; a handle's persistence is
never assumed. Helpers return bounded evidence without acquiring the program pen.
Parallel helpers write disjoint assigned files; proposed common-cache deltas stay
local until the head reconciles them. Group scratch notes are optional, born on need.

At the sitting boundary STATUS names group/task and scope revision, current phase,
exact partial result, source/diff/hash reference, last inspected receipt/review,
pending helper/effect or none, recovery probe, continuing authority and one next
action. Preserve usable results and inspect uncertain completion before retry.
Commit alone cannot identify a reviewed artifact in a dirty worktree.

Group acceptance closes only its released scope. Unavailable routes remain visibly
deferred; native method reuse does not invent a blind cross-vendor leg. Major role,
authority, canon or activation choices remain Majkee's. A source plan, a copied
stamp and a successful useful-task response are distinct evidence. A CACHE entry
does not become global doctrine without its own reviewed promotion.
