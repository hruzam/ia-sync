## Generic five-phase build loop

Resolve the frame and current group first. Then use the standing RUNBOOK workflow:

1. Local Claude/Codex harness comparison and reuse/difference map.
2. Targeted vendor-harness research; reuse adequate dated evidence across groups.
3. One building strategy, with distinct Astrobley/Houston questions where needed.
4. Scoped Luna/Terra implementation through available native roles and permissions.
5. Independent tests/audit tied to exact revision and actual exercised routes.

Done/reused/not-needed/deferred is explicit with evidence and reason. Phases do not
mean five mandatory chats, new agents or repeated permission gates. At a sitting
boundary update the same STATUS; at group disposition fold only checked common
lessons and retain exact scope/limits. A fresh window is not a fresh program.
