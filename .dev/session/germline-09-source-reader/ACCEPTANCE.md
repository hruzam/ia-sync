# G09 acceptance contract

The product goal is a lazy terminal source browser. It must discover/select/read existing
germline, temple guides and Codex/Claude skills with useful provenance. Slint, installation,
building wrappers, runtime activation and a durable global discovery index are outside scope.
Source-family details and the selected interface are frozen after R1/A1 in CONTRACT.01.json.

## Product proof

| ID | expected behavior | evidence |
|---|---|---|
| P1 | Catalog metadata from declared roots; reach/read one existing entry from each available family | Explicit root map, representative paths, exact commands and matched source bytes; absent family reported as a gap |
| P2 | Same names/vendor twins/source versus installed copies stay distinguishable | A concrete duplicate/provenance fixture plus an actual-file spot check |
| P3 | Guide resolution follows the existing guide skill contract | Slug/unique chapter success; ambiguous/absent chapter reports candidates and resolves nothing; no side-directory auto-resolution |
| P4 | Show returns selected source content without changing or executing it | Source bytes/hash comparison and before/after fixture/input-tree evidence; file instructions treated as data |
| P5 | Missing/empty roots, offline --help, noninteractive catalog/show and plain-list fallback work | Named fixture/CLI checks; no model/network call or installation needed by the product |
| P6 | Native skill visibility is distinguished from activation | Product wording makes no loaded/active claim from file presence; vendor origin and unknown provenance remain visible |
| P7 | Existing zsh brick contract respected | Thin lazy runner; syntax checks; new maintainer row only; source-tree dispatcher exercise and deploy dry-run; no actual deployment |
| P8 | Final revision is what was audited | I1/A2 exact hash map, or I2/A3 if any audited product file changed |

Auditor must independently exercise the reader, not merely approve Astrobley's test report.
It may execute authorized read-only catalog/show calls against frozen source/fixture roots,
using Python -B where applicable. It creates no fixtures, installs nothing and executes no
skill body. If sandbox restrictions block an essential check, report that criterion unverified.
No silent PASS. A missing family/root is a scoped discovery gap, not an invented empty result.

Final report: PRODUCT PASS/REVISE/UNVERIFIED; DELEGATION USEFUL/REVISE/INDETERMINATE;
GERMLINE CONTRIBUTION supported/unsupported/indeterminate with reasons and the simpler
ordinary-role/skill alternative. Product success alone proves no necessity for germline.

## Meaningful checks and limits

Use fixtures for duplicates, ambiguous chapters and unchanged input bytes. Do not add tests
that only mirror implementation branches. Run the smallest relevant syntax/fixture/CLI set,
then audit-specific checks. After correction rerun affected checks; avoid repeating everything
without a change or concern. Preserve failures before corrections.

No quantitative latency/dollar saving target is invented. No live fault, compaction or
cross-root permanence claim follows unless separately observed under this grant. Global
preamble compliance and loaded program behavior must be reported from actual turns, not
inferred from files existing or hashes matching.
