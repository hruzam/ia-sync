## Question and place in the program

Can a reader recover the same justified decision with less supplied material when
it chooses documents, rather than receiving the whole collection?

A5 found four semantic passes with every relevant document retrieved. Its explicit
routes and single historical distractor imposed little selection pressure. A9 changes
the comparison to full reading versus selective retrieval. It holds presentation and
requested model/effort constant. It does not compare table versus prose or Luna versus
Terra. Three case pairs are descriptive observations, not a general equivalence test.

`A4 supplied facts → A5 navigation → A9 reading economy → A3 S02/S07/S08` is the
evidence relationship. A3 remains design owner. A6–A8 are already allocated; identifiers
are not prerequisites. This experiment neither accepts nor closes earlier gates.

## Matched fixture and freeze

Author three independent synthetic cases. Each has **12 current documents**, exactly
four necessary evidence sources and eight plausible but task-irrelevant sources.
For a given case, both arms use byte-identical documents, task and plain Markdown
route index, in the same frozen order. Full reading receives all twelve bodies in its
initial message; selective retrieval initially receives only the common task/index.
Only the access instructions and supplied bodies differ between arms.

The index gives paths, scope and document role. It must not disclose decisive body
facts, relevance labels, answers, or the number of necessary sources. Distractors
concern adjacent components, environments or operations and have natural current
authority within those scopes. Avoid deceptive paths or ambiguous applicability.
They must not all be labelled historical, obsolete or irrelevant.

Keep documents concise and substantive: target 60–140 words each, at most 16 KiB of
UTF-8 document bodies per case and 4 KiB for its index. Do not pad to manufacture
savings. Record actual sizes and justify any shorter source naturally. Distribute the
four necessary sources through the index, with at least two irrelevant entries before
the first necessary one and at least one irrelevant entry between necessary ones.
No relevance clustering or ordering by the answer sequence. Freeze order before calls.

Desired final digest is not specified. |

For each case, author eight binary criteria before dispatch, covering:

## Dispatch, lifecycle and hard budget

and one condition, without condition labels or performance expectations. Full-reader
subjects have one admitted response turn each. Selective subjects have at most four:
initial response plus at most three same-handle continuations. Maximum **six spawns
and fifteen head-admitted response turns** for the whole pilot. No additional
advisors, retries, substitutions, crossover or corrective calls.

Wait for native completion of each requested turn before continuing the same handle.
A terminal READ is a request, not a completed task: interpret message content while
recording native lifecycle separately. The serving message after the third request
includes the frozen final-answer instruction. An invalid last request still leads
to that one final response within the four-turn limit. Earlier ANSWER ends the run.

Preserve all supplemental messages, channels and repeated requests. Never issue a
second delivery for the same already-admitted request. Count logical rounds, emitted
messages and head-admitted turns separately. A strict one-response violation qualifies
protocol compliance even when semantics pass. If a handle fails, retain the partial
attempt; no new handle or extra send is authorized to replace it. Unknown completion
requires inspecting native state and durable records before any continuation.

recovery edge. After return, persist exact messages before admitting another send.

reconcile every admission, reply, extra message and remaining budget.

## Economy accounting and decision rules

Report all six attempts and each matched pair separately. Keep semantic score,
authority errors, missing citations, protocol deviations and economy measures distinct.
Full success is 8/8 with no authority error and supported citations. No error feedback
or repair attempt is made; correction need is recorded, actual repair cost is unknown.

For each subject, compute these from the preserved transcript:

1. **D — delivered input bytes:** sum UTF-8 lengths of every head-to-subject payload,
   including task, index, access instructions, bodies, separators, unavailable replies
   and final instruction. Count a repeated delivery each time; do not count only unique
   files. Report document bytes and index/protocol overhead separately.
2. **O — emitted output bytes:** every visible subject message, including READ requests,
   final answers and supplemental messages. Keep answer length separate from retrieval
   and disclosure overhead.
3. **E — visible-history exposure proxy:** for each admitted response turn, sum the
   bytes of all visible input and prior subject messages available before that response,
   then sum across turns. Preserve arrival order for supplemental messages. This assumes
   retained conversation history and omits invisible harness/reasoning/tool state; it
   is neither measured backend tokens nor billed cost. If availability is unclear,
   report bounds or unknown instead of a precise unsupported figure.
4. Rounds, documents, necessary/irrelevant/duplicate/invalid retrievals, incomplete
   answers and protocol deviations. Record elapsed time descriptively if captured;
   do not interpret scheduling differences as a speed advantage.
5. Actual input/output/cached/reasoning usage and cost only if exposed for the relevant
   subject calls. Otherwise write unknown. No broad history/authentication/database scan,
   guessed tokenizer conversion, or price estimate from byte counts.

For each pair show `1 - D_selective / D_full` and, when defined, the corresponding E
ratio, with both correctness results beside them. No aggregate may hide a failed pair.

- A pair supports **reduced delivered material at maintained correctness** only when
  both arms fully pass and selective D is lower with valid protocol conditions.
- Lower E as well supports a stronger **visible-context economy** observation for that
  pair. Lower D but equal/higher E is an explicit tradeoff, not an unqualified economy win.
- If full reading fails, that pair cannot establish maintained baseline correctness.
  If either arm fails or is protocol-qualified, retain its descriptive metrics and
  explanation; do not silently drop it or award a clean paired success.
- Three clean pairs meeting the same rule support only a positive bounded pilot.
  Mixed outcomes remain mixed; no significance, general noninferiority, model ranking,
  monetary-saving or production-readiness claim follows from this sample.

Head preparation, fixture verification, dispatch and scoring are real experiment
overhead. Record those activities and any exposed usage separately. This pilot measures
reader-side access strategies. It does not prove end-to-end monetary savings or that a
crawler report saves the main head's context; that is a different, unreleased comparison.
