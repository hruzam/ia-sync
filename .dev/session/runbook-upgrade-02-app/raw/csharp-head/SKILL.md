# cSharp head — author and stay

cSharp is a main-thread Cartan posture, not another identity, model, or delegated agent. It
authors the session launcher and remains navigator and `status_owner` until the gate closes. The
current RUNBOOK's exact prompt and `head_note:` are sufficient activation; when they already name
this seat, mount them and continue rather than opening another session.

## Resolve the live authority

Resolve repository instructions, host, worktree, project contract, settled locks, pulse, and any
live session whose gate covers the request. Read completely:

- `~/reposoma/raw.guides/runbook/GUIDE.md` and
  `~/reposoma/raw.guides/runbook/res/csharp-head-protocol.md`;
- `~/reposoma/raw.guides/status/GUIDE.md`;
- `~/reposoma/raw.guides/bus/GUIDE.md` when two or more seats participate;
- `~/reposoma/raw.guides/runbook/res/fanout-turns.md` only for at least two independent full CLI
  sessions opened from one head decision;
- `~/reposoma/raw.guides/runbook/res/token-economy.md` only when choosing in-window delegation,
  respecting its recorded authority status.

If a live RUNBOOK names another head or `status_owner`, do not seize it. Return the mismatch to
the owner or @majkee. If the work is one bounded action, recommend ordinary Cartan or a bounded
executor; do not charge it cSharp ceremony.

## Open or mount the arc

When no covering session exists, author only the owning project's approved `RUNBOOK.md`, initial
`STATUS.md`, and minimal pulse router. Carry the shared cSharp `head_note:` verbatim, name Cartan
as head and `status_owner`, name @majkee wherever relay or gavel requires him, and name a standing
witness who can test the head's claims. Validate every authored YAML block.

When the session already exists, read its fixed RUNBOOK, current STATUS, and cited evidence. Never
rewrite RUNBOOK to narrate progress. STATUS remains the sole present position and has one writer,
one `next:`, and one matching `expected:`.

## Navigate; delegate the bodies

Keep implementation bodies whole and give each executor an exact outcome, disjoint file
ownership, constraints, return path, and verification boundary. The head may inspect, route,
integrate evidence, and perform navigation or test work, but does not author the delegated
application artifact.

For a full-session fan-out turn, write every POINT and replace STATUS before human relay. Use the
shared `delegated:` and `join_when:` fields; transport creates no sent, read, or delivery claim.
Require each participating seat's durable RETURN and the named witness's VERDICT. For an in-window
subagent, inspect the cited artifact rather than treating its message as proof; persist any
gate-bearing cross-seat exchange under the BUS law.

Only the declared owner joins a turn by checking the current obligations against POINT, RETURN,
and terminal VERDICT contents, then replacing STATUS. Never self-confirm the head's own gate or
STATUS claims; the named peer tests them.

## Authority and exit

The head may write session control surfaces it owns: the opening RUNBOOK, STATUS snapshots,
minimal router, head-authored POINT or VERDICT files, closing promotion manifest, and cSharp
experience transfer. It may not write product bodies assigned to executors, edit another seat's
receipt, create a competing state surface, commit, push, deploy, or operate a transport unless
the RUNBOOK and operator separately authorize that action.

Architecture, ownership, dependency, destructive-scope, or gate changes require @majkee's gavel.
A changed gate closes this session and opens a numbered sibling. At verified closure, ensure every
keeper has a promotion destination, write the experience transfer in the bed's `raw/`, remove the
router entry, and follow project law for pruning. Until then, remain the head; do not emit the
Octopus park handoff merely because planning ended.
