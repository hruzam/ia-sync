# Reader controller — candidate 03

Purpose: expand inherited context only far enough to make the next bounded decision
or action supportable. Read [README.md](README.md) for entry and knowledge roles.
The head keeps integration and authority; tools and helpers supply evidence.

## Inputs and outputs

Inputs: assignment; current phase/checkpoint; permitted source roots and effects;
relevant pointers; inherited claims and open uncertainties; operator constraints.

Outputs: a supported next action or a precisely stated information boundary;
source-backed changes to working understanding; preserved anomalies; an intake or
result receipt in the session's already assigned evidence home. No separate live state.

## Procedure

1. **Recover position.** Read current STATUS and governing entry instructions. If a
   previous action may have run, inspect its receipts/observable effects before any
   repeat. Distinguish a missing return from a failed operation.

2. **Name the decision.** State the immediate question and the fact that would change
   the next action. Map only its implicated contracts, decisions and receipts. If the
   assignment itself is ambiguous, seek the missing scope; more crawling may not help.

   If the question concerns session state, recover the relevant disposition history:
   explicit CLOSE records, acceptance decisions and correction/addendum chains. Do
   not decide from the first YAML block, a folder number, file mtime or last paragraph
   alone. Resolve authority and temporal scope; preserve any unresolved conflict.
   For retired sources, use the project's declared archive registry and exact original
   identity. An archived STATUS explains history; it is not a live instruction to run.

3. **Assess inherited claims.** For each consequential claim, resolve may-inherit,
   must-verify and invalidation conditions from the entry account and source. Check
   current authority and relevant supersession routes as well as content revision.
   A changed hash triggers impact analysis, not automatic rejection of all old work.
   For consequential reads, record relevant source revisions before and after the
   read/crawl. Detected changes make affected claims provisional pending
   reconciliation. Equal endpoints are not a transactional snapshot guarantee.

4. **Choose the smallest useful read.**

   | Situation | Choice |
   |---|---|
   | One known decisive contract or receipt | Head reads the relevant complete contract/receipt directly |
   | Location unknown across several permitted sources | Delegate a bounded mapper if authorized, or perform the same scoped search locally |
   | Two revisions or explanations conflict | Delegate a comparison or hypothesis scout; head inspects decisive evidence |
   | Task merits search for unanticipated omissions | Assign a separately bounded frontier pass; do not imply exhaustive coverage |
   | Summary already answers the task but its decisive source is missing | Return the gap; do not promote a useful-sounding answer to authority |

   State the benefit expected from delegation: bounded search breadth, an isolated
   comparison, anomaly coverage, or less exploratory material entering the head.
   Compare that benefit with setup, helper reading, report intake, verification and
   correction effort. When only a few decisive sources are known, start with direct
   reading. A justified context-isolation benefit may involve more total work; do not
   equate it with economic savings. The choice grants no new source or effect authority.

5. **Issue a crawl assignment when appropriate.** Use [crawl-bots.md](crawl-bots.md).
   Name question, allowed roots, expected discriminator, actual budget, artifact
   location and return size. Give the relevant inherited claims and known gaps;
   exclude unrelated conversation. Start with one helper. Broaden or parallelize
   only when independent questions justify it and delegation is authorized.

   Choose and record requested role/model/effort and context policy for the question.
   A role name such as crawler or explorer does not specify price or model tier.
   Give a bounded brief where sufficient; inherit broader context only for a stated
   need and account for it. When dividing sources among helpers, name the join question
   and overlap. Follow-up facts shared by the head make this coordinated collection,
   not independent audits. Record observed runtime evidence separately from requests;
   copied parent metadata must not be mistaken for a child's own identity or work.

6. **Integrate with verification proportional to consequence.** Inspect decisive
   cited passages before changing architecture, ownership or an effectful action.
   Recheck decisive current passages if sources changed during the crawl; do not
   present a mixed-revision account as one coherent current contract.
   For routine retrieval, check that cited paths and passages support the extraction.
   Record disagreement and reader inference separately from source words. An omitted
   area in the report remains unknown. An unexpected relevant tail may change the
   question; account for that change instead of hiding it in the original schema.

7. **Stop or expand deliberately.** Stop when the evidence supports the next action
   within the grant and unresolved questions no longer block it. If the next decisive
   source is outside the grant, return its locator and why it is needed. If the budget
   is consumed, report partial coverage. An additional crawl needs a named information
   gain; repeated vague searches are not progress.

8. **Leave usable inheritance.** The head writes the checked result to the existing
   evidence home, updates affected understanding/pointers, and rewrites STATUS after
   the verified transition. Preserve who/what/why/revision/supersession where material.
   Give useful unresolved findings a scope owner or explicit disposition. Before
   pruning or transferring, check actual preservation and successor intake.
   Before yielding or dispatching further work, also preserve consequential partial
   or blocked returns and anomaly locators, labelled unverified where appropriate.
   STATUS names unfinished integration; a temporary agent message is not its custody.

## Paper walk: caretaker returns after P1 became P2

The head inherits that a caretaker ran an operation using P1; current state points
to P2. It first checks the operation receipt to establish whether effects occurred.
It then reads the authoritative change decision. If the affected dependencies span
several files, a bounded comparison helper identifies P1/P2 differences and points
to evidence about the returned result. The head verifies the decisive difference,
reuses still-valid evidence and marks only the invalidated conclusion for revision.
A contradiction or absent receipt is returned as uncertainty. No automatic repeat
of the original operation follows from an incomplete report.

This walk is a design example. No runtime recovery or economy claim is established.

For a fresh intake or substantial recovery, use the
[continuity-receipt template](continuity-receipt.template.md) within the assigned
result home. Preserve a partial/blocked receipt too; successful reconstruction is
not a prerequisite for recording what the transfer cost or failed to carry.

## Bounded trial proposed for A3

Use separate fresh reader contexts for ordinary direct reading and this contract,
with the same assignment, authority and frozen fixture containing both revisions.
Neither route sees the other's answers. Include an adequate entry, a sparse entry,
one relevant source change, a misleading summary and an outlier
outside the expected structure. Score correct decision, source/authority mistakes,
missed relevant tail, unnecessary rereads, correction effort, elapsed time and main
intake volume. Record entry/setup, helper, verification and correction effort, and
helper intake/output and tool/model usage where actually exposed;
report unavailable measurements. Less main context does not establish lower total cost.

Required result: a fresh head acts correctly, recovers the omitted detail, rejects
the misleading summary and reports its search limits. Any economy recommendation
must include setup and integration costs. Trial dispatch is separate from this draft.
