## Contract to freeze before the first run

The POINT specifies behavior but not CLI syntax, numeric exits, literal log schema or state vocabulary. The following are **proposed trial expectations**, not adopted canon or a claim about an implementation that has not been delivered. Trajectory’s build ring must publish the helper invocation, bounds, state/attempt locations and actual public mapping. If its numeric/string mapping differs, append the mapping here and commit it **before** running any case. Preserve the behavioral criteria; never change an expected outcome to fit an observed result. An incompatible behavioral contract returns to the head before testing.

Proposed exit mapping: `0` carrier acceptance/attempt, `20` unknown recipient, `21` dead target, `25` duplicate/retained uncertain key, `29` unknown signature/identity, `31` bounded wait exhausted. An exit zero alone does not prove submission or consumption. Literal `event=`/`reason=` names in the table are proposed log predicates; freeze their actual spelling before runs. Each record must correlate UTC, logical message ID, recipient, carrier, attempt and outcome without secrets.

Proposed `@state` meaning: the most recently supported **target observation**, e.g. `ready`, `busy`, `occupied`, `needs_approval`, `dead`, `unknown`. A delivery timeout is an attempt error in the log; it does not establish that the target ceased to need approval or that its draft disappeared. If the build uses `@state` for attempt status instead, the head must identify a separate observable frozen-on-approval signal before this case can pass. `queued`, `delivered` and `consumed` must not be inferred solely from screen quietness or absence of a dialog.

Before execution, freeze a finite wait budget and interval using the helper’s supported controls. Suggested sample-only values: 5s total, 1s interval; completion deadline = configured bound +2s process/scheduling allowance, with actual timings reported. No CLI or production setting is changed to create these controls. If the helper cannot use a short bound, declare its actual finite budget before the run. Never let a case become an unbounded watcher.
