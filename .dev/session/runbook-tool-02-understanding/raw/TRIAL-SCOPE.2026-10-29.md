# Historical disposable trial proposal — not the current next action

Disposition updated 2026-10-30: unapproved and unexecuted. Cartan withdrew this as the
recommended next step after discussion; see REENTRY.2026-10-30.md.

Purpose: determine whether a living view improves entry enough to justify maintenance,
compared with the accepted source-pointer baseline. This document is a proposal only.

Use a separately numbered successor bed if released. Keep all fixtures and results there;
no live project state, deployed files, guide edits, external transport or runtime actions.

Build one synthetic session with a fixed gate, P1 procedure, an approved same-gate P2
procedure change, and a return based on P1. Prepare two presentations of identical facts:
(A) RUNBOOK/STATUS plus exact evidence pointers; (B) the same sources plus a short attributed
living view. The view deliberately retains one stale P1 interpretation after P2 so the
trial tests source checking rather than trust in a polished summary.

Run four fresh, history-free native reader consultations: two per presentation, identical
model/settings and task, with every reader permitted to read all fixture sources. Ask each
to identify the effective procedure, safe next action and reusable/missing parts of the
old return. Include seven explicit variants: stale STATUS, partial return, changed return,
wrong binding, unknown execution, late return and duplicate dispatch. All actions are
written recommendations; nothing is executed. A separate read-only reviewer checks
answers against an owner-authored answer key frozen before reader dispatch.

Record correctness per case, source reads where observable, elapsed time, owner correction
count, unsafe recommendations and effort to maintain the view after the change. Record
tokens only if actually supplied. Do not equate elapsed time with human work or cost.

Acceptance: zero unsafe recommendations; all readers must recognize P2 and reconcile the
P1 return. Compare retrieval burden descriptively. Prefer the baseline if the view produces
no clear benefit or creates additional stale-summary errors. Four consultations establish
feasibility only, not reliability or statistically demonstrated savings.

Stop if fixture ambiguity prevents scoring, a reader attempts live execution, or scope
escapes the synthetic bed. Report the failure instead of silently revising the answer key.
Maximum: four reader consultations plus one bounded reviewer, no repeated tuning rounds.

Requested approval: this synthetic fixture and consultation scope only. After results,
Majkee decides whether any further implementation is worth doing.
