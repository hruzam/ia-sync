## Direction from majkee (voice, this session — not yet gaveled)

1. **Every operational instruction is a program.** Majkee's frame is the application tree
   (Laravel / OpenCart): controller = the process · model = the information structure the
   process works on (state files, schemas — not a prose layer) · functions = bounded jobs ·
   the vendor skill/agent = the final class, a thin loader.

   one agent like Houston's cards. Rewiring agents onto them is later work.

   (what a guide subchapter carries today).

5. **Maintenance fear:** guide subchapters + programs side by side = double upkeep and an unclear
   sort. The rule below exists to kill that.

## The sort rule (proposed)

> **Does an agent run it? → program (germline). Is it read to understand? → guide (book).**

No procedure in a guide, ever — one home per step, so "both" cannot drift. A command found in a
guide is a fold-out finding, not a style note. This is also the existing B′ law
(guide-writing/GUIDE.md §The law: executable → table, knowledge → temple); v3's model-shape put
procedure under `raw.guides/` and so ran against it.

## Proposed shape (Atlas — for you to challenge)

```
germline/
  agents/<slug>/          who: identity · binding · cards        (exists — Houston)
  programs/<slug>/        what job — shared by any reader
    controller.md         invariants · model (pointers to the data structures + schema) · functions table
    fn/<verb-object>.md   one occasion: occasion: + stamp:, exact commands, specific failure paths
  skills/skill.<slug>.md  (exists)
```

- The vendor wrapper is a loader only: read `controller.md` → the matching `fn/` → quote both
  `stamp:` tokens (Houston's runtime-load + stamp rule, reused — no new mechanism).
- Inheritance depth capped at Houston's chain (base → binding → addendum → function). Deeper is
  flattened at render time, never left to the reader — the compiler is stochastic.

## The two v3 contract defects — resolved by this shape

- **Direct function reads bypass invariants** (`/guide <slug> <fn>` → `res/` directly, guide
  SKILL.md:23): dissolved. The loader is the only entry; the controller is always read first;
  stamps prove it.
- **L1 "rule the controller … lacks" vs the sort test / Wave R1 (scoped rules live in functions):**
  needs the scope test — *a rule is an invariant if a reader on another occasion could breach it,
  or its breach is costly/irreversible; otherwise it is scoped and lives in its function.* L1 drops
  "or lacks"; a missing costly rule is L2.
