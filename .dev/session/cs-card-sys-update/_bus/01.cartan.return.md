## Codex-native rendering

- **Flat vault:** the execution contract names only top-level `issues/`, `routines/`, and
  shared `archive/`. It explicitly deletes the former nested subtree and separate reaction
  type in one migration note so stale behavior cannot survive by omission.
- **Fix-manual:** the issue body holds observed evidence and the fix or response playbook
  once known. There is no separate reaction artifact.
- **Three-path fold:** known-recurring defects go directly to `routines/`; solved one-shots
  move from `issues/` to `archive/`; a later recurrence moves the archived card into
  `routines/`. Moves remain per-card operator decisions.
- **Dual origin signal:** a graduated issue keeps its `ISS.<slug>.<YYYY-MM-DD>.md` name and
  original date as “first seen,” gains `origin: issue`, and is never renamed to `RT.`. A
  born routine is identified as `RT.*` plus `origin: intended`; optional `from_issue:` is
  limited to a split rather than a wholesale move.
- **Parked:** deferral is encoded as the `parked` association plus a body note containing
  the reason and exit condition. It is neither a folder nor a `status:` value.
- **Retrieval floor:** the card template and run gate require at least seven real,
  filterable `assoc:` entries and forbid invented filler tags.
- **Sort reconciliation:** dated cards sort by the filename `YYYY-MM-DD`; a missing marker
  surfaces in `UNSORTED`; date extraction is stated separately from forbidden filename
  kind inference. Born `RT.*` routines are exempt, while graduated `ISS.*` routines retain
  the date as “first seen.”
- **Launcher metadata:** `agents/openai.yaml` now asks for a defect and its fix with the
  correct flat-vault fold path; it no longer advertises reaction cards.
