## The base and its tasks

`WORKLINE.md` is the sequential task journal. Work on one selected task, record its
result and exact completed or unfinished scope, then select the next. Keep the
shared brief here and update it when the process actually teaches something.

A task may be a direct bounded adjustment, a design discussion, preparing a
RUNBOOK, or executing a separately authorized session. There is no requirement
that every task fork, create a RUNBOOK, or run an agent build.

Use the runbook planning protocol when the selected task needs a fixed acceptance
gate, separate working context or handoff. Its RUNBOOK stays fixed and STATUS owns
live execution. The A0 journal links that session and its returned result; it does
not duplicate its next action or acquire its STATUS pen. A0 itself currently has
no executable RUNBOOK, STATUS or pulse entry.

## Working sequence

1. **Brief/select:** read the common process and select one concrete agent/project task.
2. **Size/design:** name its scope, owner, allowed files and observable completion;
   use a separate design context or RUNBOOK only when the task needs one.
3. **Perform:** do the authorized task, or deliver its prepared RUNBOOK when that is
   the task. Preparing a launcher does not release its execution.
4. **Verify/record:** link the evidence and mark the exact completed part, plus what
   remains. Fold supported process lessons into this base; then take the next task.

“Fork” remains an optional bounded task context, not a promised native mechanism,
retained child or automatic dispatch. The selected task names its actual route.
