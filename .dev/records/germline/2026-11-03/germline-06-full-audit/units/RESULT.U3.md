## 10. Addendum 2026-10-21 — invocation-grammar field survey (Epoch, attributed; `_bus/epoch.grammar.U3.return.md`)
Live-verified (clig.dev; MCP draft Tools spec; Anthropic "Define tools", all accessed 2026-10-21): CLIs favour **space-separated `noun verb`** (`docker container create`, `gh pr list`) — trivially tokenizable, shell-safe; task runners favour **`ns:task`** (Rake, npm scripts, go-task) — safe in shell, collides with `key: value` in YAML and `scheme:` URLs; agent-tool names favour **dotted/underscore identifiers** (MCP allows `A-Za-z0-9_-.`, e.g. `admin.tools.list`; the Claude API regex `^[a-zA-Z0-9_-]{1,128}$` forbids dots). **`&`/`&&`** are shell operators: pasted raw into zsh, `ctrl journal-continuity&audit-beds` backgrounds `ctrl journal-continuity` and runs `audit-beds` as a second command; `&` is also the URL query separator; Epoch found no CLI convention using `&` as a namespace separator (memory, not exhaustive). Three forms most favoured for *program + function + free text*: `program function: text` (or `-- text`), `program:function text`, `program.function` / `program_function`. Per-tool rows beyond the three verified sources are training memory (M); Google/Microsoft/12-factor CLI guides were not searched.
**Flight note:** reported as the field, not a recommendation — Majkee named the line as his and the composer's; the choice is his and touches Composer's grammar (C1, Cartan), so it goes to the handoff as an operator-direction item. The engineering constraint that does bind any choice: the separator must survive paste into a shell, a YAML value and a Markdown line, because the same line lives in journal entries and briefs.
