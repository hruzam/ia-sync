# Review

Review the current changes with a code-review mindset.

## Required behavior

1. Focus on bugs, regressions, risky assumptions, and missing tests.
2. Ground findings in the actual changed code.
3. Prioritize the most severe issues first.
4. If there are no meaningful issues, say so clearly.

## Output

Present:

1. Findings first
2. Open questions or assumptions
3. Short summary of change scope

Avoid turning the response into a changelog unless the user explicitly asks for that.
